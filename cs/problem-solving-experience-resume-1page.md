# 문제 해결 사례 요약 (이력서 1페이지)

## 대규모 트래픽 쿠폰 발급 시스템 성능/정합성 개선

### 프로젝트 배경
- 선착순 쿠폰 발급 API에서 트래픽 증가 시 성공률 급락, 응답 지연, 데이터 정합성 문제(중복 발급/불일치)가 발생.
- 목표는 고부하에서도 정합성을 유지하면서 응답 성능을 안정화하는 것.

### 내가 해결한 핵심 문제
1. **동기 처리 병목(DB 커넥션 풀 포화)**
2. **중복 발급 및 수량 불일치(정합성 문제)**
3. **비동기 처리 실패 시 보상 부재**
4. **고부하에서 에러 응답 경로 지연**
5. **Kafka vs @Async 기술 선택 근거 부족**

### 주요 개선 사항
- 요청 경로를 비동기 이벤트 구조로 분리: `수량 확인 -> 이벤트 발행 -> 즉시 응답`
- 실제 발급 저장은 백그라운드 소비자로 분리하여 DB를 응답 경로에서 제거
- Redis를 수량의 단일 기준으로 통일하고, DB 유니크 제약으로 최종 중복 방지
- 중복 이벤트 idempotent 처리(이미 처리된 요청은 재처리하지 않음)
- 발행/소비 실패 구간별 보상 트랜잭션 설계
  - 발행 실패: 즉시 수량 원복
  - 소비 실패: 1회 보상 마커로 과보상 방지
- 공통 예외 처리로 고부하 에러 경로 단순화(즉시 409 반환)
- Kafka와 @Async를 동일 조건으로 반복 비교해 선택 근거 확보

### 성과 (요약)
- 고부하 구간에서 평균 응답시간과 안정성 유의미 개선
- 중복 발급 방지 및 수량 정합성 확보
- 단발 테스트가 아닌 반복 실험(워밍업/재시작 분리)로 결과 신뢰도 확보
- 병목 지점이 DB에서 애플리케이션 수용량으로 이동함을 확인, 다음 확장 전략의 기준 수립

### 기술적으로 기여한 포인트
- 병목을 코드 단위가 아닌 시스템 경로(API -> Queue -> DB) 단위로 분석
- 정합성 보장을 애플리케이션 로직 + 저장소 제약 + 재시도 정책으로 통합 설계
- 성능 개선을 수치 기반으로 검증(Before/After, 반복 측정)
- 운영 관점(장애 복구, 재시도, 보상, 관측성)까지 포함한 구현

### 사용 기술
- Java, Spring Boot, JPA, MySQL, Redis, Kafka, k6
